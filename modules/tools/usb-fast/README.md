# digikit/usb-fast

File uploads on a USB bulk interface, several times faster than SysEx. A run-time module (`.dkm`) in C; it needs `core/usb-bulk` (the adapter that adds interface 2,
EP2 OUT and IN, to the USB MIDI mode) and, on the Digitakt II, `core/plusdrive-write` for the +Drive. Plan: `docs/plans/usb-fast.md` section 5 and
`docs/plans/usb-fast-hardware.md` (step 4). Selected, the device re-enumerates once at boot and offers the bulk interface; not selected, USB is stock and SysEx
does everything as before.

- **SysEx**: `USB_FAST_NONCE` (0x36, range `usb_fast` of `sdk/sdk.toml`): body 8 bytes, empty reply. `TAKEOVER` (0x1e) and `RELEASE` (0x1f, range `usb_fast_takeover`): the host has core/usb-bulk switch a device in USB AUDIO/MIDI to USB MIDI for a transfer and back ([plan](../../../docs/plans/usb-fast-takeover.md)); TAKEOVER also renews. `STATUS` (0x37) is a debug aid: 20 words, word 8 is `usb_bulk_state` (the host reads its wrong-mode bit); body `'S' ...` is the speed mask (below). STATUS words 18 and 19 are the staging reservation in bytes and the ring slots of the live block, for the hardware A/B. The host sends random bytes, then asks INFO on each
  candidate USB device and keeps the one that returns them (the USB serial strings are the same on every unit).
- **Speed switches**: `STATUS` body `'S' [bit [0|1]]` reads the four switches or sets one (RAM only, all on at boot, never saved) and replies the mask (u32). Bits 0 and 2 live in the runtime's speed word (SDK `speed_flags`), bit 1 in core/usb-bulk (`usb_bulk_ring`), bit 3 in core/sdhc-large (`sdhc_large_ctl`); setting a bit of an adapter that is not in the image is E_STATE. Bit 0: hash once (DN2 store: the received bytes are not hashed when BEGIN carries the host hash; the close's card read-back is the only hash and must equal it), bit 1: USB receive ring, bit 2: the read-back hash runs on the runtime's helper task while the next piece is read (DN2 store and the DT2 +Drive close hash), bit 3: large card commands. STATUS bodies dispatch by their first byte through `status_tab` in `usb-fast.c`: one line per tag.
- **Bulk protocol** (`[protocol.bulk]`): request `'DKB1' | cmd | seq | flags u16 | len u32 | body`, reply `'DKB1' | cmd|0x40 | seq | status i16 | len u32 | body`.
  INFO replies `version, flags, window, reserved, data_max, align, nonce[8]`: `window` is the receive window in DATA frames of 64 KiB (core/usb-bulk's ring: 12 with 60 slots; 0 from an older device or with the ring off: the host keeps 2 in flight). A host that asks INFO keeps that many DATA requests in flight (`BulkSession`, `dkbulk`); a reply still means "accepted": the bytes are in the ring or the staging buffer. BEGIN (`root, path, size, hash4`; flag REPLACE) opens a file with `file_create`, DATA
  (`offset, bytes`) writes with `file_write`, END closes with `file_close` and replies the 4-byte `hash|1`, ABORT drops the file. VERIFY is reserved and answers
  `E_PROTO`: the host verifies over SysEx.
- **Stream**: frames are cut by their length field, not by USB buffers: a frame may span receive buffers and a buffer may hold several frames. Each frame is copied
  into one 16-byte-aligned buffer (so `file_write` gets an aligned pointer) and each receive buffer is released as soon as its bytes are copied. A bad magic or a
  length over `data_max + 4 + frame_slack` is fatal for the stream: the module replies `E_MSG` for the seq it saw, drops what it holds and the open file, and reads
  the next bytes as a new stream.
- **Busy**: a `file_*` call that answers `E_BUSY` is called again (the runtime waits 1 ms) up to 3 times (BEGIN 400 times, about 0.4 s: the +Drive staging folder is removed after an idle session), then the host gets `E_BUSY`. No receive buffer: the job
  sleeps and the adapter wakes it; the host is NAKed while the ring is full. Replies are queued (16): a send that finds both slots in flight does not stop the stream, so a host that sends 12 frames before it reads a reply never deadlocks the ring.
- **Staging before ring**: the module reserves its staging buffer (1 MiB, else 256 KiB) before the adapter allocates its receive ring (at TAKEOVER, or in the enable step when the device is in USB MIDI mode), keeps it for the session and frees it when the adapter's buffers are gone or at unload; each file uses as much of it as it needs. On a tight heap the ring then takes the smaller tier, not the staging buffer. Static evidence: the 32 MiB buddy heap has about 27 to 29 MB free with a project loaded and a largest free block of 16 MiB (findings 41, 47), so 1 MiB + 1 MiB is expected to fit on both devices (the staging buffer comes first from the module arena when that can give it).
- **Reset**: a bus reset or a disconnect (the reset count of `usb_bulk_state` changes) aborts the open file and clears the parser.
- **Enable**: the job calls `usb_bulk_enable` until it succeeds: the adapter wakes it four times a second while the device is not in USB MIDI mode or a mode switch is settling.
- **Idle session**: the runtime drops a write session with no write for 20 s; the job frees its staging buffer 1 s later.
- **Build flags** (`src/c/uf.h`): `UF_TRACE`, `UF_BENCH` (the storage bench, `src/c/uf-bench.c`) and `UF_KNOBS` (STATUS 'A', the staging buffer test knob) are 0 in shipping builds; the staging buffer test skips its forced-size cases without `UF_KNOBS`.
- **Unload**: `dkm_fini` disables the interface and cancels the job; the runtime aborts a file the job leaves open.
- **Test**: `tests/usb-fast.device.test.ts` (emulator, both devices) over `EmuBulkLink` of `packages/dk-session`.
