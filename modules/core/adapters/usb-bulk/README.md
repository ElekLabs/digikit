# core/usb-bulk

A vendor bulk interface (interface 2, EP2 OUT and IN, 512-byte packets) added to the firmware's USB MIDI mode, for run-time modules: `usb_bulk_enable`,
`usb_bulk_take`, `usb_bulk_release`, `usb_bulk_send`, `usb_bulk_state`, `usb_bulk_takeover`, `usb_bulk_giveback` and `usb_bulk_ring` (`sdk/sdk.toml`, `sdk/include/dk/platform/usb_bulk.h`). Plan: `docs/plans/usb-fast.md`
section 4; facts: `docs/findings/42-usb-transfer-routes.md` section 4. EP2 IN runs with 64-byte packets and no zero-length termination, like the firmware's EP1 IN, because the controller's TX buffer holds 64 bytes per endpoint and two back-to-back 512-byte IN packets wedged it on the DN2.

- **No firmware patch.** The USB engine is the same code at the same addresses on DT2 1.17 and DN2 1.12. Its port table is RAM: `usb_bulk_enable` checks
  the stock entry 2 (callbacks, length, the 101 descriptor bytes), then writes four words (connect, disconnect, descriptor pointer and length) and
  re-enumerates with the firmware's own stop and restart pair. Not called, nothing is written and USB is stock. Outside USB MIDI mode (USB CONFIG) enable
  prepares the entry only (the next switch to USB MIDI enumerates with interface 2: one enumeration for a take-over) and returns E_STATE until the device is in USB MIDI mode and no
  switch is settling; bit 2 of `usb_bulk_state` shows the wrong mode live. While enabled, the adapter wakes the module's job four times a second (a timer for the module).
- **Take-over** (`docs/plans/usb-fast-takeover.md`): `usb_bulk_takeover` records the original port (USB AUDIO/MIDI, port 5) and a request; `usb_bulk_tick` (UI task, on the runtime's
  `dkrt_poll_add` list from the first take-over call on, also while bulk is not enabled) calls the firmware's mode switch (`cf.usb.fn.mode_switch`) with port 2 at least 50 ms
  later. `usb_bulk_giveback` and the automatic give-back (the disconnect callback, a bus suspend of 0.5 s, 30 s without a transfer or renew) switch back the same way. After each of these switches the adapter holds the firmware's restart for 2 s (counter 60 instead of 30), releases the PHY's line while the controller is stopped (ULPI function control through ULPI_VIEWPORT, written back before the restart; `UB_ULPI_DETACH 0` turns it off), waits for a reply on EP0 or EP1 IN before it switches and 3.5 s between switches, and forces the firmware's restart when USBCMD.RS is still clear 4 s after a switch with VBUS present (`usb_bulk_forced_restarts`). Facts and reasons: `docs/findings/123-usb-takeover.md`. Refused in
  Overbridge. A port change by another route drops the state without a switch. The USB CONFIG setting byte is never written (test: `cf.usb.value.config_mode`). Bit 3 of the state word.
- **Anchors** (`devices/fw/usb.toml`): the port table, the active port, the USB CONFIG setting byte, the firmware's restart delay counter, connect, disconnect, queue, cancel, dTD allocation, stop, restart and the mode switch.
- **Receive ring**: up to 60 slots of 16 KiB (960 KiB; four 4 KiB pages each: every dTD names all five page pointers) in the uncached alias of DDR, allocated per session with
  the send slots as one block (a 1 MiB block from the firmware's buddy allocator; the tiers are tried 60, 28, 8 slots, so a heap that cannot give 1 MiB gives 512 KiB, then the old 256 KiB block with 8 slots;
  all tiers refused: E_NOMEM, ST_NOMEM, nothing enabled). At most 12 dTDs are queued on EP2 OUT at once (the firmware's pool has 31, 2 are ours for EP2 IN); the completion callback, in the interrupt,
  marks the slot full, queues the next free slot round the ring and wakes the module's I/O job (`dkrt_io_wake`), so the controller keeps receiving while the job writes the card. The job takes the full slots in
  arrival order. No free slot: nothing queued, the host gets NAK. A 64 KiB frame of usb-fast spans five slots, so the ring takes 12 frames (`usb_bulk_ring` reports it). The run-time switch
  (`usb_bulk_ring`, bit 1 of the usb-fast switch mask, default on; `usb_bulk_ring_off` in the emulator test) off: 8 slots, all queued, the old geometry; it is read when the buffers are allocated and at every queueing. Switching it off while buffers are live keeps the block and only stops queueing beyond 8 slots; a session that starts with the switch off allocates the 8-slot block, which is the clean A/B. `usb_bulk_ring` returns bit 0 the switch, bit 1 always set (the SDK stub returns 0 for an adapter without it), bits 8..15 the window, bits 16..23 the slots of the live block.
  **Send**: the bytes are copied into one of two slots and queued on EP2 IN.
- **Reset**: the connect and disconnect callbacks cancel both EP2 queues with a bounded flush (the stock disconnect polls without a bound), drop buffers
  that were full and not taken, and change the reset count of `usb_bulk_state`.
- **USB_SW events** (log kind 44, level info, except STATE at debug level: raise usb-bulk's level with LOGCFG, `dklog level` or the workbench Level menu to see STATE; needs `digikit/debug`): the timeline of one take-over or release, from the accepted request until the host has configured the device (DONE) or 10 s have passed (TIMEOUT). The tick samples the controller once a pass; at most 32 events a switch (STATE stops at 24; DONE, TIMEOUT, GIVEUP and DROPPED always log). FW_SWITCH, HOLD_BEGIN and PHY_PARK are logged after the PHY is parked, with the time and register words stamped right after the firmware's switch. The callbacks that run in the USB interrupt only count and stamp; the tick logs them. Layout of the five words:

  | Word | Content |
  | --- | --- |
  | a0 | bits 0-7 phase, 8-11 target port, 12 direction (0 take-over, 1 release), 13-15 detail (try, result 0 ok / 1 failed, or wait reason 1 guard / 2 in flight), 16-31 switch number (low 16 bits of `usb_bulk_switches`; the number this switch gets) |
  | a1 | ms since the request (callbacks: the stamped time) |
  | a2 | bits 0-15 USBSTS low 16 bits (URI 6, PCI 2, SLI 8), 16 USBCMD.RS, 24-31 last ULPI function control value seen (0xff unknown) |
  | a3 | PORTSC (callbacks: the copy taken in the interrupt) |
  | a4 | bit 0 OTGSC.BSV, 1 FRINDEX changed since the previous sample, 2 EP3 TX active (ENDPTSTAT or ENDPTPRIME bit 19), 8-14 DEVICEADDR.USBADR, 16-21 endpoint enables (EP1 RX, EP1 TX, EP2 RX, EP2 TX, EP3 RX, EP3 TX), 24-31 connect callback count (low 8 bits) |

  Phases: 1 REQ, 2 WAIT (once; the switch is due but the guard or a reply in flight holds it), 3 FW_SWITCH (the firmware's mode switch returned), 4 DISCONNECT_CB, 5 HOLD_BEGIN, 6 PHY_PARK, 7 PHY_RESTORE, 8 RS_UP (USBCMD.RS is 1 again after the stop), 9 CONNECT_CB, 10 ADDRESSED (RS_UP seen, a bus reset seen since the switch (connect callback, URI, or USBADR 0) and USBADR non-zero), 11 CONFIGURED (an EP1 enable after ADDRESSED of an earlier pass, with the EP1 enables seen 0 since the switch), 12 STATE (a sampled word changed and no milestone fired), 13 ENUM_LATE (no ADDRESSED 3 s after RS_UP; stale state from before the switch cannot satisfy ADDRESSED or CONFIGURED), 14 RECOVERY (detail: try), 15 GIVEUP, 16 DONE (a1: total ms; detail 1: 2 s after ADDRESSED without CONFIGURED), 17 TIMEOUT, 18 DROPPED (a pending request ended without a switch: the mode changed or a give-back came during the take-over delay; closes the window). A release in USB MIDI mode without a switch (taken from USB MIDI) logs nothing.
- **Emulator**: FRINDEX is not modelled, so the SOF bit (a4 bit 1) stays 0 there (the FRINDEX read is still a register read per sample); DEVICEADDR and ENDPTCTRL1 to 3 store what the guest writes. The controller is not modelled, except that ULPI_VIEWPORT completes at once and `usb.phy` (`docs/CONTROL.md`) lists the PHY accesses and USBCMD.RS changes. `usb.bulk.in` and `usb.bulk.out` (`docs/CONTROL.md`) complete the dTDs through the guest's own callbacks.
  Test: `tests/usb-bulk.device.test.ts` with the fixture `test/usb-echo`.
