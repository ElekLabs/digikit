# Firmware analysis

Use `uv run python -m tools.coldfire.fw` from the repository root to build,
query, and review firmware. Select a release with `-i IMAGE` or
`--device NAME --firmware VERSION`. Use `--core main` for the main OS and
`--core dsp` for the DSP.

| Firmware file to place in `firmware/` | Release directory | Main OS | DSP |
| --- | --- | --- | --- |
| `Digitakt_II_OS1.17.syx` | `dt2-1.17` | ColdFire | SHARC |
| `Digitone_II_OS1.12.syx` | `dn2-1.12` | ColdFire | SHARC |
| `Syntakt_OS1.42.syx` | `st-1.42` | ColdFire | ColdFire |

The device profiles select the instruction set for each core. Syntakt's DSP
appears as `st-1.42-peer-emac` in the Ghidra dump and SQLite image metadata.
Use `--core dsp` to query its address space.

## Generate a SHARC catalog from a SysEx

From the repository root, with the Python dependencies installed:

```sh
uv run python -m tools.coldfire.fw review --syx /path/to/Digitakt_II_OS1.17.syx --core dsp
```

Use either Digitakt II OS 1.17 or Digitone II OS 1.12. The command identifies
the stock release by hash, so the file can have any name. It extracts the
firmware, builds the SHARC database and writes
`out/firmware/<release>/dsp/review.html`. Open that file in a browser. No
Ghidra dumps or second firmware file are needed.

For paired function links, provide the second file with `--other-syx`. This
builds both catalogs and writes both review pages in their default locations.
An optional `--out` adds an alternate copy of the first review in paired mode. Add `--format json` for a
`reviews` array on stdout with one record per page, including `release`, `core`,
`cpu`, `firmware_sha256`, `peer` (null for standalone SHARC), and absolute
`database`, `html`, `tsv` and SHARC `addrmap` paths. Build progress goes to stderr. Register the
reported `firmware.sqlite` in [Workbench → Settings → Firmware symbols](ADDRMAP.md#firmware-symbols-in-desktop-settings).

Search the HTML by address, name or role. **Address map (JSON)** opens the same
symbol data used by the CLI. Function links end in `#r-0x<entry>`, using the entry address shown in the review
TSV. Keep the two review paths relative to each other when moving paired
pages. If the catalogs already exist, [re-export the HTML](#find-and-open-the-output)
with the release key.

SHARC rows show a static estimate for one call of the function itself,
with loop body size, literal or symbolic trip counts, and unresolved calls.
Use `fw cost ADDR -i RELEASE --core dsp --format json` to include callees or
substitute trip counts. Values are instruction estimates. Board cycles
require a profile from hardware. [Firmware cost and symbol workflow](ADDRMAP.md#open-a-profile-hotspot)

## Build the databases

Extract the firmware sections and prepare the ColdFire dumps. For Digitakt II
and Digitone II, use the [Ghidra workflow](TOOLS.md#coldfire-static-analysis-and-ghidra)
to generate `out/ghidra/dt2-1.17-emac` and `out/ghidra/dn2-1.12-emac`.
For Syntakt, prepare both `st-1.42-emac` and `st-1.42-peer-emac` using the
[Syntakt Ghidra commands](findings/70-syntakt-1-42.md#analysis-databases).

```sh
uv run python -m tools.firmware.extract firmware/Digitakt_II_OS1.17.syx -o out/sections/dt2-1.17
uv run python -m tools.firmware.extract firmware/Digitone_II_OS1.12.syx -o out/sections/dn2-1.12
uv run python -m tools.firmware.extract firmware/Syntakt_OS1.42.syx -o out/sections/st-1.42

uv run python -m tools.coldfire.fw build -i dt2-1.17 --other dn2-1.12
uv run python -m tools.coldfire.fw build --device syntakt --firmware 1.42
```

These builds populate both cores for the selected releases and print catalog row
and group counts. Pass `--core main` or `--core dsp` to build a single program.
For the paired `fw build` workflow, pass `--other` with the second SHARC release.
SHARC uses the extracted DSP sections. ColdFire imports the matching Ghidra dumps.

## Find and open the output

Each core has the same layout under `out/firmware/<release>/`.

```text
<release>/
  main/                       Main OS
  dsp/                        DSP
    firmware.sqlite           Functions, analysis tables, and searchable catalog
    review.html                Browsable catalog, generated by fw review
    exports/
      catalog.tsv             Candidate functions and evidence
      groups.tsv              Call-graph group summaries
      graph.json              Candidate nodes and call edges
      review.tsv              Complete review inventory, labels, and links
```

Browse each `firmware.sqlite` with a SQLite viewer or query it with `fw sql`.
Both instruction sets expose `functions`, `catalog` and `catalog_groups`.

| Program | What the database contains |
| --- | --- |
| ColdFire main OS | Functions, cross-references, strings, disassembly, decompiled C, and semantic atlas tables for descriptors, parameters and UI classes |
| ColdFire DSP | Functions, cross-references, disassembly, decompiled C, and call-graph groups for the DSP program |
| SHARC DSP | Decoded instructions, call edges, loops, memory references, function hashes, and the recovered function inventory in `function_index` |

Workbench can load the ColdFire main OS and SHARC DSP databases as symbol
sources. Browse the separate Syntakt DSP database with a SQLite viewer or
`fw sql --core dsp`. [Firmware symbols in Workbench](ADDRMAP.md#firmware-symbols-in-desktop-settings)

Run `review` for each page you want to browse. Generate both pages for paired
links, and keep their paths relative to `out/firmware/` when moving them.

```sh
uv run python -m tools.coldfire.fw review -i dt2-1.17 --core dsp
uv run python -m tools.coldfire.fw review -i dn2-1.12 --core dsp
uv run python -m tools.coldfire.fw review --device syntakt --firmware 1.42 --core dsp --all
```

Open the generated `review.html` in a browser. SHARC review pages show the complete catalog by default. Use `--all` to show
the complete ColdFire catalog. `exports/review.tsv` always contains the full
catalog. Add JSONL review labels in the core's `labels/` folder or pass
`--labels FILE`. The exporter also reads the earlier `out/atlas/labels/`
folders when the core's folder has no labels. Export any saved browser
decisions from the old page as JSONL and import them in the new page if needed.
[Review labels and browser decisions](DEVELOPMENT.md#coldfire-ui-candidate-review)

`fw` can read databases from earlier builds under `out/cfdb/` and
`out/sharcdb/`. When those paths are free, `fw build` creates compatibility
links for older tools. Existing files at the old paths are preserved.
`out/sections/` holds extracted inputs and `out/ghidra/` holds analysis dumps.
Firmware and generated output are local to the checkout.

## Query the catalog

```sh
uv run python -m tools.coldfire.fw catalog -i dt2-1.17 --core dsp --groups
uv run python -m tools.coldfire.fw search q31_converter -i dt2-1.17 --core dsp --in catalog
uv run python -m tools.coldfire.fw sql 'SELECT count(*) FROM functions' --device syntakt --firmware 1.42 --core dsp
```

The SQLite `catalog` and `catalog_groups` tables back the query CLI and the
review export. [Firmware query command reference](TOOLS.md#firmware-query-cli-and-the-atlas)
